# Cloud 后续推进清单

> 这份文档用于记录当前 `cloud/` 学习版工程在后续几轮中的推进顺序，避免同时发散到太多方向。

## 当前已完成
- `gateway-service / user-service / education-service` 三服务骨架
- Nacos 注册发现
- Gateway 显式静态路由
- OpenFeign 最小调用链
- `user-service` 真实查库用户校验
- `education-service` 发布作业真实业务链
- Nacos Config 第一层
- JWT 最小登录与 Gateway 鉴权
- 身份透传头替代显式 `publisherId`
- 统一返回与异常处理第一层
- 日志第一层

## 后续优先级

### P0：日志继续收口
- 明确哪些日志长期保留
- 后续是否增加 `WARN / ERROR` 细分
- 保持不打印敏感信息

### P0：Cloud 文档继续维护
- 服务职责
- 接口边界
- 配置归属
- 认证与授权边界
- 迁移进度

### P1：逐步迁移单体未迁移业务链
建议按业务链迁移，而不是整体搬迁：
- 查询作业列表
- 学生提交作业
- 教师评分
- 其他围绕课程/作业的接口

### P1：前后端接口对齐
- 统一前端请求入口到 Gateway
- 逐步适配新的：
  - 统一返回结构
  - 登录方式
  - 认证上下文设计

### P2：阶段性结构优化
- 继续收服务内部结构
- 是否需要调整测试接口位置
- 是否需要补更多异常语义（例如 403）
- 是否逐步把更多配置迁到 Nacos Config

## 当前不建议
- 一次性整体迁完单体后端
- 过早新增更多微服务模块
- 过早做完整认证体系（refresh token、黑名单、多端登录）
- 过早做复杂公共模块抽象

## 当前主线原则
- 一次只推进一条清晰链路
- 优先把已经落地的结构沉淀成规范
- 每完成一个阶段，就做一次 commit 和一次复盘
